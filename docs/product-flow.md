# 这一顿的自由画布

本文定义产品方向与目标流程；当前已经可用的内容见[当前画布与餐次入口](features/home-canvas/feature.md)。

日常主要由用户和对象共同使用：打开当前这一顿的画布，自由加入想吃的菜和其他内容，在同一处摆放、修改、补充和商量，逐渐决定今天吃什么。决定之后，在家完成这顿饭；这顿结束后进入历史，之后可以回看、写备注、添加多张照片。用餐前的决定和吃完后的记录是两个不同阶段，定下吃什么，并不代表这顿已经吃完。

```mermaid
flowchart LR
    A[打开当前这顿的画布] --> B[添加内容和想吃的菜]
    B --> C[共同编辑与商量]
    C --> D[决定今天吃什么]
    D --> E[在家用餐]
    E --> F[结束并进入历史]
```

## 画布中的共同决定

自由画布是整个产品的主体。菜是其中最核心的内容，大家也可以自由加入其他内容，让这张画布承载这一顿的想法与表达。添加、摆放和修改都属于共同决定的过程，用户可以边编辑边商量，不必先选完菜才进入画布，也不需要完成所有装饰才能往下走。

日常以两人共同使用为主要场景，但这不构成只能两人参与的限制。家庭关系承载长期协作，页面和操作围绕当前这一顿的画布展开，弱化模式选择与切换。

## 来客加入同一张画布

家里来了朋友或客人，他们通过临时身份进入当前这一顿，加入同一张画布，和日常参与者一起添加内容、修改想法、完善画布，并共同决定今天吃什么。参与者发生了变化，大家仍然围绕同一顿饭协作，结束后留下的也是这同一顿的记录。

临时身份表达的是本次参与，不改变来客的长期家庭归属。来客可以和日常参与者共同编辑这一顿的画布。

## 吃完后留下完整的一顿

历史需要保留四类内容：实际吃过的菜、画布当时的样子、备注和多张图片。回看一顿饭时，既能知道吃了什么，也能看到大家当时共同留下的表达，以及用文字和照片补充的用餐经历。

历史直接承载这顿饭的回忆，画布的保存形式由实现设计确定。

菜谱提供可以复用的菜品资料，也是向当前画布加菜的来源。如果使用买菜清单，它负责辅助准备这一顿需要的材料。这些内容都围绕当前画布展开，帮助大家从想吃什么走到实际吃上这一顿。

## 尚待明确的边界

临时身份如何认证、共同编辑以外的来客权限、参与有效期，以及历史中的画布是否可以再次编辑，目前尚未明确，不补充默认规则。
