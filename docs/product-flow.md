# 产品场景与主流程

## 产品定位

Lover Order 是家庭一起决定吃什么、安排当前餐次并记录用餐过程的工具。首页画布是共同决策和表达这一顿饭的工作区，不是独立的海报编辑器。

## 三个核心对象

### 家庭

家庭是长期关系，由两人或多人组成。家庭成员共享菜谱、当前餐次、购物清单和历史记录。

### 餐次

餐次是一次具体的吃饭事件。家庭成员可以添加菜品、整理画布、写下想法，最后确定这一顿并在吃完后记录。

### 聚餐

聚餐是家庭餐次的临时变体。家庭成员从当前餐次发起临时点菜房间，朋友通过链接或扫码加入这一顿。朋友只参与当前聚餐，不加入家庭关系。

## 首页主流程

1. 进入家庭，查看当前餐次。
2. 从菜谱或输入框添加想吃的菜。
3. 在画布中拖动、整理和删除菜品。
4. 添加文字、表情、动效、画笔和背景，表达这顿饭的主题与心情。
5. 点击“定下这一顿”，表示家庭已经完成决定。
6. 吃完后点击“记录吃完”，保存菜品、画布、参与者和评价。

画布中的元素必须可以准确选中、取消选中、拖动和删除。选择状态不能阻塞其他元素或底部工具栏；编辑工具打开时，内容应直接展示效果，避免用户依赖抽象的小图标猜结果。

## 聚餐流程

1. 家庭成员在当前餐次发起聚餐。
2. 系统生成临时点菜房间。
3. 朋友通过链接或扫码加入。
4. 所有人在同一餐次中添加菜品和编辑画布。
5. 家庭成员确认这一顿。
6. 吃完后保存为聚餐记录。

聚餐不会创建第三种产品场景，也不会改变家庭成员关系。

## 状态与记录

- 准备中：可以添加和编辑内容。
- 已确定：表示这一顿已经决定；如需调整，必须明确进入修改状态。
- 已完成：保存为历史记录。

普通家庭餐次使用 `household`，临时朋友聚餐使用 `dining`。历史页面可以按这两类筛选，并恢复查看当时的画布和菜品。

## 辅助功能

菜谱用于提供可复用的菜品信息；购物清单用于准备食材；评价用于记录吃完后的感受。它们都服务于家庭餐次，不抢占首页画布的主流程。
